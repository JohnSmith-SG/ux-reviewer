# UX-рецензент сайта — ИИ-агент, который делает UX-аудит страницы по ссылке

Вставляете адрес страницы — агент сам скачивает её, разбирает структуру (заголовки, меню, кнопки,
формы, картинки), передаёт UX-эксперту на gpt-4o и возвращает отчёт: **оценку 1–10, достоинства,
слабые места и ровно 5 рекомендаций** с приоритетом и основанием — на какой цитате или факте со
страницы держится каждый совет.

*AI agent that turns any URL into a UX review: score, strengths, weaknesses and 5 prioritized
recommendations, each backed by evidence from the page. Python · OpenAI API (gpt-4o, structured
outputs) · BeautifulSoup · tenacity · FastAPI · Docker Compose · GitHub Actions.*

## Как работает агент

```
run(url)
  1. fetch     — скачать HTML (только публичные адреса, сам проходит редиректы, лимит 3 МБ)
  2. extract   — заголовки H1–H3, меню, кнопки и призывы, формы, картинки без alt,
                 мета-описание, viewport, видимый текст
  3. ask_json  — gpt-4o с ролью UX-эксперта, ответ строго по JSON-схеме
  4. check     — формат (ровно 5 рекомендаций, оценка 1–10) и смысл: не советует ли модель
                 то, что на странице уже есть → иначе повтор (до 3 попыток)
  → UXReport: score, site_type, summary, strengths, weaknesses, recommendations[5]
```

## Решения, которые стоит отметить

- **Факты считает программа, а не модель.** Есть ли адаптация под телефоны, у всех ли картинок
  есть описание, сколько форм — это посчитано по HTML и передано модели блоком «проверенные
  факты». На первых прогонах gpt-4o советовала «добавить alt» сайту, где alt уже был у всех
  картинок. Теперь такой ответ ловит проверка и запрашивает новый. Так же считаются контакты
  (Telegram, почта, телефон): на длинном лендинге раздел «Контакты» стоит в самом конце, и модель
  советовала «указать контакты», не видя его. Поэтому модели уходит до 14 000 знаков видимого
  текста — типичный лендинг целиком, а у страниц длиннее берутся начало и конец.
- **У каждой рекомендации есть основание** — цитата или факт со страницы. Общие советы
  «улучшить навигацию» без привязки к странице промпт запрещает.
- **Структурированный ответ.** `response_format: json_schema` со `strict: true`: модель не может
  вернуть «почти JSON», приоритеты — только из списка «высокий / средний / низкий».
- **Повторы через tenacity** — до 3 попыток при сетевых сбоях, 5xx, лимитах и «битом» ответе.
  Ошибки 4xx (ключ, баланс) не повторяются: повтор их не исправит.
- **Защита от SSRF.** Сервис скачивает любые ссылки, поэтому пропускает только http(s) на портах
  80/443 и хосты с публичными IP. Каждый редирект проверяется заново: внутренняя сеть сервера и
  служебные адреса облака (169.254.169.254) недоступны.
- **Бережём деньги.** Лимит проверок в сутки с одного адреса и общий дневной потолок. Одна и та
  же страница в течение суток отдаётся из кэша, не больше 2 проверок одновременно. IP хранятся
  только как хэш с солью.
- **Честность о границах.** Агент читает HTML, а не картинку страницы: дизайн и цвета он не
  видит и не делает вид, что видит. Сайты, которые полностью строятся скриптом в браузере,
  агент распознаёт и честно об этом сообщает.

## Запуск

```bash
python -m venv .venv
.venv/Scripts/pip install -r requirements.txt        # Linux/macOS: .venv/bin/pip
cp .env.example .env                                  # вписать PROXYAPI_KEY (или OPENAI_API_KEY)

python agent.py https://example.com                   # отчёт в терминале
python agent.py https://example.com --json            # отчёт в JSON
uvicorn app:app --port 8080                           # веб-сервис: http://127.0.0.1:8080
```

По умолчанию используется ProxyAPI (`https://openai.api.proxyapi.ru/v1`, модель `openai/gpt-4o`).
Для прямого OpenAI задайте `OPENAI_BASE_URL=https://api.openai.com/v1` и `UX_MODEL=gpt-4o`.

### Docker

```bash
docker compose up -d            # готовый образ ghcr.io/johnsmith-sg/ux-reviewer:latest
docker compose up -d --build    # или собрать локально
```

Образ собирает GitHub Actions при каждом push в `main`: сначала `mypy --strict`, потом сборка и
публикация в GitHub Container Registry. На сервере `deploy/update.sh` скачивает свежий образ и
перезапускает сервис, если вышла новая версия (вручную или по cron). Ключ API в образе не
хранится — на сервере он монтируется файлом (`PROXYAPI_KEY_FILE`).

## API

| Метод | Что делает |
|---|---|
| `POST /api/review` `{"url": "…"}` | UX-отчёт (JSON); 422 — страницу не загрузить, 429 — лимит, 502 — нейросеть не ответила |
| `GET /api/limits` | сколько проверок осталось сегодня |
| `GET /health` | проверка, что сервис жив |

## Структура

| Файл | Назначение |
|---|---|
| `agent.py` | агент: загрузка страницы, извлечение UX-признаков, промпт, проверка ответа, `run(url)`, командная строка |
| `openai_module.py` | клиент OpenAI-совместимого API, structured outputs, повторы (tenacity) |
| `app.py` | веб-сервис FastAPI: API, лимиты, кэш, журнал проверок (SQLite) |
| `static/index.html` | страница сервиса: форма, ход проверки, карточки отчёта, копирование отчёта |
| `Dockerfile`, `docker-compose.yml` | контейнер и запуск |
| `.github/workflows/docker.yml` | проверка типов и сборка образа |
| `deploy/update.sh` | обновление сервиса на сервере |
